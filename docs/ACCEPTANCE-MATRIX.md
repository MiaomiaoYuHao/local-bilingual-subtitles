## 关键机制

- 来源顺序：官方软字幕/播放器 DOM → 硬字幕 OCR → 语音 ASR。
- 无硬字幕：9 秒探测无稳定字幕 → 自动关 OCR，只走 ASR。
- OCR/ASR 运行时交叉验证：连续 2 行 ≥0.55 关 ASR 省 CPU；连续 2 次 <0.45 关 OCR 并清掉 OCR 行。
- 逐行来源：`ocr` / `asr` / `ocr-video`（保留在内部数据与验收状态中；1.5.29 起弹窗不再显示来源、行数或中文条数）。
- OPFS：短直链内存抓取、长直链 SW 流式 OPFS、可 fetch blob 端口上传、MSE blob 提取 media-video 直链。
- 内部自动缓冲：软字幕加载后自动全量预翻译；整段 ASR 返回带时间戳 segments；画面 OCR 自动选择实时取帧或 OPFS。弹窗不显示缓冲状态，也没有预处理按钮。
- 低对比 OCR：主阈值失败时生成对比拉伸版做二次识别；音频在 VAD 裁静音后做 85Hz 高通与峰值归一。
- 长音频：实时是 4s 窗口 + 2s 重叠；离线大音频必须分片（Chrome 单条消息 64MiB）。

## 已知限制

1. MSE 页面若完全不暴露 media-video/media-audio 直链，仍需 MSE 分片解析。
2. 快速连读/强音乐 ASR 仍可能有个别误识别。
3. OCR 在低对比/小字/贴边字幕上仍可能漏词；B 站个别片段会粘连。
4. YouTube 软字幕需要用户打开 CC；不打开时依赖 OCR/ASR 兜底。
5. B 站 `player/v2` 的 `subtitle_url` 可能为空；1.5.21 已优先读播放器 DOM 字幕。
6. WebGPU 在本机 ASR 实测输出乱码且慢，生产继续用 WASM。
7. 内部整段 ASR 上限 30 分钟；更长视频需要流式分片，接近上限的耗时/内存峰值尚未验证。

## 1.0.51：切视频后还会播上一条字幕（已修）

原因有两个，都在"站内切换不刷新页面"时暴露：

1. YouTube 适配器把"播放器自己发出的字幕数据"存进了一个全局数组（最多 8 条），**切视频时没清**；新视频解析字幕时又把旧数据一起喂给解析器，于是继续出旧台词。
2. 主控里 `resolveSubtitles` 用 `state.resolving` 做互斥：切视频时若上一条视频的字幕解析还在路上，新的一次会被直接跳过，而**旧结果回来后又写进了新窗口的缓存**。

修法：适配器给每条捕获数据记上视频 ID（`timedtext` 地址里的 `v=`），解析时先丢掉不属于当前视频的；主控加 `resolveToken`，切视频/卸载视频时作废在途结果，过期结果一律丢弃。

| 验收点 | 结果 | 证据 |
| --- | --- | --- |
| 站内切视频（不刷新页面） | 通过 | `Shift+N` 从 `aircAruvnKk` 切到 `IHZwWFHWa-w`，URL 变化、页面未重载 |
| 切换后不再出现旧台词 | 通过 | 30 秒采样：旧视频台词（"This is a 3." 等）在切换 8 秒后 0 次出现 |
| 切换后显示新视频台词 | 通过 | 显示 "As a reminder, our goal here is the classic example…"，与播放器原生字幕一致 |

## 1.0.53：空笔记保存会把旧内容拼回来（已修）

原因：页面端/离屏端在追加前先读了一份**按文件名缓存的内部副本**（IndexedDB texts），只有缓存没有时才去读文件。
所以当笔记被清空、或新建了同名笔记时，缓存里的旧全文仍然在，追加结果 = 旧全文 + 当前 3 条。

修法：改成**先读磁盘文件**——文件空就是空、文件有内容就用文件的内容；内部缓存只在"读不出文件"（例如被 Word 锁住）时兜底。
「新建」同时清掉同名缓存，并且写出的新笔记是**空文档**（不再把文件名当第一行）。

| 验收点 | 结果 | 证据 |
| --- | --- | --- |
| 空笔记读回是"空"而不是 null | 通过 | 单测 `buildFromText("")` → `extractTextFromDocx` 返回 `""` |
| 空笔记首次保存只写当前三条 | 通过 | 单测：写入后读回内容 === 当前三条，无旧内容 |
| 第二次保存 = 老内容 + 一个空行 + 新内容 | 通过 | 单测：行数/分隔符断言 |
| 真实文件演示 | 通过 | `node tools/check-empty-note.mjs`：空笔记 1247B → 追加 → 只含当前三条 → 再追加 9 行（空行分隔） |

## 1.0.54：每次按保存都重复存一段（已修）

根因：`requestSW()` 返回的**已经是 data**，但主控里写成了 `res.data.ok` / `res.data.reason`，判定永远不成立。
于是本地助手成功写完一段之后，代码以为「没存成功」，继续往下走到老的「页面文件夹」分支，把同一段又写了一遍。

同一个写法还导致走「扩展面板里设置的文件夹」时永远认不出成功（历史上「又要确认位置」的来源之一）。

修法：改成 `res.ok` / `res.reason`；并新增保护：要写的这一组与笔记里最后一组完全相同时直接跳过，提示「这段已经保存过了」。
